# G1 审核检查项

本文件定义“查什么”和“需要什么证据”；结论和优先级以 `SKILL.md` 为准。

## A. PRD 准出检查

| 检查组 | 必查内容 | 阻断条件 |
| --- | --- | --- |
| 背景、目标、范围 | 目标用户/业务对象、当前问题、可观察目标、本期范围和非目标 | 无法判断本轮做什么或目标结果 |
| 角色与权限 | 主要角色、进入条件、可见/可编辑/可操作边界 | 权限差异会改变结果但未定义 |
| 流程与分支 | 入口、前置、主流程、关键分支、完成结果、回退路径 | 核心路径不闭环或关键分支无处理 |
| 字段与数据 | 字段含义、类型、必填条件、默认/空值、格式/范围/枚举、示例 | 设计无法确定展示、输入或校验含义 |
| 状态与异常 | 正常、加载、空、失败、异常、禁用、处理中、状态迁移 | 关键状态缺失或状态变化影响操作却未定义 |
| 边界与恢复 | 触发条件、处理方式、用户反馈、取消/返回/重试/重复操作/失败恢复 | 重要边界只有“提示错误”而无业务结果 |
| 验收与元信息 | 可验证 AC、版本、维护人、更新时间、变更记录、待确认项 | 关键行为无法验收，或版本/待确认事项不可定位 |

## B. 原型初稿准出检查

| 检查组 | 对照内容 | 阻断条件 |
| --- | --- | --- |
| 范围与入口 | PRD 页面、用户、终端、入口和必要界面 | 核心页面/入口遗漏 |
| 主流程与分支 | 从入口到成功结果的操作路径及关键分支 | 核心流程走不通或关键分支无入口 |
| 字段与文案 | 字段、枚举、正式文案、顺序、默认值和成功落点 | 与 PRD 冲突或关键字段缺失 |
| 状态与权限 | 正常、加载、空、失败、异常、禁用、权限差异、处理中 | 关键状态/权限操作未体现且无说明 |
| 边界与反馈 | 触发、处理、反馈、取消、返回、重试和恢复 | PRD 已定义行为在原型中没有对应路径 |
| 复用项 | PRD 的复用声明，以及复用项下另行写明的规则 | 复用声明本身不判；附加规则与原型冲突时阻断、缺失时需补齐 |
| 设计交接 | 页面可读取、可继续编辑，模拟数据能支持讨论 | 文件无法打开或无法定位关键区域 |

## C. PRD—原型一致性映射

每条核心需求记录：

| 字段 | 证据要求 |
| --- | --- |
| 需求依据 | PRD 路径、版本、章节或 `G/FR/BR/IR/AC` |
| 角色/前置 | 进入角色、权限和数据条件 |
| 页面/操作 | 页面、区域、入口、动作、返回和跳转 |
| 结果/状态 | 成功、失败、取消、重试、状态变化和用户反馈 |
| 原型证据 | HTML 行/区域、组件区域或可复现操作路径 |
| 结论 | 一致 / 缺失 / 冲突 / 未验证 / 复用 / 待判断 |

“页面有按钮”不能证明业务已覆盖；必须能回扣到结果、状态或验收标准。

复用项按 `SKILL.md` 3.1 不判；多状态项记 `待判断`，交人工确认。

## D. 可选量化指标

只有在 PRD 或团队标准明确采用时才计算，并写清分母、排除项和版本：

- 初稿分支覆盖率建议 ≥95%；
- 初稿边界规则覆盖率建议 ≥90%；
- 正常、空、加载、失败、异常五类基础状态至少体现 3 类。

量化结果是辅助证据。核心流程、权限、业务结果或关键状态缺失时，不能用平均覆盖率放行。

## E. 非本次 G1 核心检查

- 使用了哪个 Skill 版本；
- 是否提交完整制作说明；
- 是否完成全部静态门禁；
- 视觉像素级还原、完整组件审查和开发测试环境验收。

这些内容可作为附加证据或后续 G2/G3 工作，不得替代 PRD—原型一致性检查。

## F. 复用项与多状态

**复用项判定**

| 情形 | 处置 |
| --- | --- |
| PRD 只声明复用，未附加规则 | 不判。原型可不包含；结论写 `复用` |
| PRD 声明复用，且在复用项下写了规则 | 按原规则判：冲突 → 阻断；缺失 → 需补齐 |

判定依据仅为 PRD 原文，不需要线上环境或线上截图。

例：PRD「批量操作栏复用其他知识类型的线上实现；**新增按钮在无权限时置灰**」——前半句不判；后半句若原型未置灰记阻断，若完全没做记需补齐。

**多状态**

PRD 明确列出多个状态（正常 / 加载 / 空 / 失败 / 异常 / 禁用 / 处理中 / 权限差异等）时：

- 技能不下结论，不判缺失、不判一致；
- 按 `建议` 级别记入问题区，标注交人工判断；
- 不计入阻断 / 需补齐，不影响结论。
