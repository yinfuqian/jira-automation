# 技术方案准出 Checklist

## 1. 定位

本清单是 Jira 从“开发设计中”流转到“开发中”的 G2 技术方案准出正式判定依据，也是技术方案进入 OpenSpec `propose` 和开发实施的唯一准出入口。

- **入口状态**：开发设计中。
- **目标状态**：开发中。
- **提交角色**：方案设计者。产品架构师或研发均可承担，不新增岗位。
- **参与角色**：产品经理、产品架构师、研发、测试。
- **最终确认角色**：产品架构师。
- **正式结论**：通过 / 退回补充。

G2 只判断 `{需求名称}_功能描述与技术方案.md` 的核心实现路径、核心契约和验证入口是否足以让开发接管并进入 OpenSpec `propose`。G2 不以文档完整度或架构细节丰富度作为准出条件，不检查代码是否已经实现，也不要求 OpenSpec tasks 或 Jira 执行子任务在准出前已经生成。

## 2. 权威来源与准出输入

- PRD 是当前需求唯一业务事实源。
- `{需求名称}_功能描述与技术方案.md` 是当前需求唯一技术设计事实源。
- 原型、图示、截图和交互稿定义页面结构、入口、控件、文案、状态和交互；没有原型时，以用户确认记录为界面事实依据。
- `Project.md`、现有接口与配置、数据库结构、日志和测试材料用于解释当前项目约束；G2 不校验代码基线、实现完成度，也不要求逐行对照代码。发布包中的 `Project.md` 如标注为 Bot 项目样例，实际项目必须使用自己的项目上下文。
- Jira 提供需求范围、状态、责任和问题闭环记录。
- OpenSpec 在 G2 通过后消费技术方案，生成 proposal、spec、design 和 tasks，不重新猜测产品事实或关键技术决策。

正式判定前必须能够唯一定位：

- Jira 主单。
- PRD 文件或链接。
- 技术方案文件或 Jira 关联材料。
- 涉及原型时的原型文件或用户确认记录。

输入冲突时不得由 Agent、研发或 OpenSpec 静默选择。业务事实以 PRD 为准，方案未承接或改写 PRD 时判定为不满足；技术事实冲突由方案设计者调查并修订技术方案。

## 3. 判定原则

### 3.1 可实施性与阻断判定

技术方案应明确核心实现路径，使开发人员无需补充业务事实或重新选择关键技术方案。出现下列任一明确情形时，判定为阻断：

1. 技术方案不可定位，或与 PRD 在目标、范围、角色、规则、状态、权限、文案或验收结果上冲突。
2. 关键业务链路、系统边界或核心实现路径无法确定，且会导致开发无法实施。
3. 核心接口、数据或状态契约缺失或相互矛盾，且会改变外部行为、数据含义或权限结果。
4. 命中权限、租户、敏感数据、不可逆操作或核心数据写入时，缺少必要的安全或失败控制。
5. 关键功能或关键失败场景没有可识别的验证入口，或存在无法执行的发布、回滚约束。

仅涉及代码组织、命名、内部实现方式或非关键优化的差异，不构成阻断。背景叙述、备选方案比较、非关键章节、监控指标、实施顺序细化和非核心证据缺失，不作为退回理由。

### 3.2 足够进入 OpenSpec propose

技术方案必须已经明确任务拆分所需的边界、依赖和禁止自行推断项。G2 不要求提前写出全部 OpenSpec tasks，也不要求详细实施顺序；只要求 `propose` 阶段不需要重新决定业务规则或关键技术方案。

### 3.3 前后端同等可落地

前端与后端采用同一标准判断。涉及页面或交互时，技术方案应基于原型或用户确认，说明页面入口、核心交互、状态来源、请求失败结果、权限结果和验证入口；组件复用、技术选型、兼容性、性能和完整交互细节可以按需补充。仅当这些内容缺失导致页面行为、权限结果或验收入口无法确定时，才按第 3.1 节阻断。纯后端需求应说明前端不适用及依据。

## 4. 检查项等级

| 等级 | 含义 | 准出影响 |
|---|---|---|
| `MUST` | 所有需求必须检查的核心契约 | 核心契约无法确认或存在明确阻断时退回补充 |
| `CONDITIONAL` | 命中触发条件后执行检查 | 仅影响核心实现、数据权限结果、测试验收或发布安全的缺失才阻断；其余不阻断 |
| `SHOULD` | 有助于提高可实施性、可验证性或可维护性 | 不单独阻断，但需记录取舍 |
| `OBSERVE` | G2 后仍需验证的技术假设或线上指标 | 不得承载会改变实现、测试或发布路径的未决事项 |

`N/A` 只用于 Agent 内部标记未命中的场景项，不作为退回项，也不输出。核心契约无法确认、核心内容相互矛盾或存在第 3.1 节明确阻断情形时，按“不满足”处理；非核心证据缺失、章节缺失、表述不够详细或非关键内容无法唯一判断，不作为退回理由。

## 5. `MUST`：所有需求必查的核心契约

- [ ] **G2-M01 输入与事实源**：Jira 主单、PRD 和技术方案可定位；方案没有重新定义目标、范围、角色、规则、状态、权限、文案或验收结果；方案与 PRD 在业务事实上没有明确冲突。
- [ ] **G2-M02 核心链路与实现路径**：关键业务链路、系统边界和核心实现路径能够唯一确定，足以从入口走到最终结果；前端需求同时说明页面入口、核心交互和状态来源。
- [ ] **G2-M03 核心接口、数据与状态契约**：实际变更涉及的接口或消息、数据、状态和权限结果一致；请求、响应、关键错误语义以及进入退出条件没有会导致不同实现的缺口。
- [ ] **G2-M04 高风险场景控制**：实际涉及权限、租户、敏感数据、不可逆操作或核心数据写入时，后端鉴权、资源归属、失败控制和恢复方式明确；未涉及时不适用。
- [ ] **G2-M05 验证入口**：关键功能和关键失败场景存在可识别的测试或验收入口；验证依赖无法执行时，已明确关闭条件。
- [ ] **G2-M06 开发接管与任务约束**：改动范围、关键依赖和禁止自行推断项明确，开发可直接进入 OpenSpec `propose`，无需重新决定核心业务或关键技术逻辑。

证据定位规则：G2 按技术方案的实际内容取证，不要求固定章节标题或完整架构说明。核心结论缺失、核心内容冲突或存在第 3.1 节明确阻断情形时，对应检查项判定为不满足；非核心章节、备选方案、指标、任务排序或证据不够详细，不作为退回理由。

## 6. `CONDITIONAL`：命中场景后必查

触发场景只代表需要检查。命中后按第 3.1 节判断是否存在明确阻断：影响核心实现、数据权限结果、测试验收或发布安全的缺失按“不满足”处理；其余缺失作为改进建议，不阻断 G2。未命中时由 Agent 内部判定为 `N/A`，不作为退回项，也不输出。

### 6.1 `G2-C01` 普通 CRUD

触发：单模块、低风险、无复杂状态、无跨系统副作用和迁移。

- [ ] 权限、资源归属、唯一性、分页、排序、批量和数据合法性边界明确。
- [ ] 接口失败、数据不存在和重复提交有明确结果；仅涉及不可逆或高风险发布时，缺少可执行回滚才构成阻断。
- [ ] 未触发的复杂状态、分布式一致性和压测项有不适用依据。

### 6.2 `G2-C02` 核心数据写链路

触发：核心数据新增或修改、不可逆动作、多个写步骤或业务副作用。

- [ ] 唯一约束、状态 Guard、事务边界和失败顺序明确。
- [ ] 幂等键、并发控制、补偿、对账和数据修复可执行。
- [ ] 核心 SQL、索引、数据规模和执行计划按实际风险提供事实或验证计划；非关键优化细节不单独阻断。

### 6.3 `G2-C03` 多系统同步协作

触发：多个服务或外部系统共同决定最终结果。

- [ ] 权威数据源、系统责任、协议、时序和失败归属明确。
- [ ] Deadline、重试、熔断、降级、部分成功和晚到结果明确。
- [ ] 不把不可控远程调用无保护地放入本地事务，并明确补偿与对账方式。

### 6.4 `G2-C04` 异步任务、消息、回调或批处理

触发：使用消息、异步任务、回调、定时任务或批处理。

- [ ] 消息或任务契约、Key、版本、顺序和大小边界明确。
- [ ] 生产失败、数据库提交关系、重复消费、乱序、积压和重放结果明确。
- [ ] 幂等、重试、死信、补偿、对账和用户可见状态明确。

### 6.5 `G2-C05` AI、LLM 与外部智能服务

触发：调用 AI、LLM、NLP 或模型推理服务，或模型输出参与业务结果和外部副作用。

- [ ] 调用契约、服务标识、鉴权、租户上下文、Deadline 和错误映射明确。
- [ ] 输出格式或 Schema、语义、安全、权限、权威状态和动作合法性校验明确。
- [ ] 超时、拒答、非法输出、安全拦截、降级、人工兜底、晚到结果和副作用保护明确。
- [ ] 质量门槛、关键切片、Token、时延、成本和验证口径明确。
- [ ] 模型参数、实验配置和候选模型可以在实施前继续细化，但不得替代失败策略和业务结果。

### 6.6 `G2-C06` 高并发或高可用

触发：存在明确容量、并发、稳定性或故障恢复要求。

- [ ] QPS、P95、并发、数据规模、故障预算和容量上限有事实或明确验证计划。
- [ ] 限流、隔离、线程池、队列、拒绝策略、热点保护和降级明确。
- [ ] 缓存击穿、锁竞争、依赖故障扩散和压测通过标准明确。

### 6.7 `G2-C07` 存量系统改造

触发：修改已有入口、调用方、公共能力、配置或隐藏契约。

- [ ] 现有调用方、数据、配置和隐藏契约已调查并有证据。
- [ ] 新旧行为、兼容期、灰度、回归范围和退出计划明确。
- [ ] 没有把现有实现偶然行为直接当成产品规则。

### 6.8 `G2-C08` 数据迁移

触发：新增、清洗、回填、切换或删除存量数据。

- [ ] 迁移范围、批次、顺序、限速、停机和在线策略明确。
- [ ] 清洗、校验、对账、失败续跑和重复执行结果明确。
- [ ] 双读、双写、切换条件、最终收口和不可逆数据补偿明确。

### 6.9 `G2-C09` 兼容性改造

触发：数据库、接口、消息、配置、依赖或客户端版本发生变化。

- [ ] 目标版本范围和新旧调用方混用行为明确。
- [ ] 字段类型、分页、保留字、索引、协议和配置差异已验证。
- [ ] 契约版本、废弃期、发布顺序和回退策略明确。

### 6.10 `G2-C10` 前端页面与交互改造

触发：新增或修改页面、路由、组件、表单、列表、前端状态或用户交互。

- [ ] 页面结构、入口、控件、文案、状态和交互来自原型或用户确认，没有自行补设计。
- [ ] 页面、路由、组件、状态管理和 API 适配职责明确，复用与新增边界清楚。
- [ ] 加载、空数据、错误、无权限、重复提交、取消、失败恢复和深链状态明确。
- [ ] 请求触发、缓存、竞态、取消、超时、重试和重复提交策略明确。
- [ ] 前端校验与后端最终校验边界明确，权限显隐不替代后端鉴权。
- [ ] 浏览器或客户端兼容、大数据量处理、前端性能和自动化或人工验证方式明确。
- [ ] 关键页面行为、接口调用和测试入口明确。

### 6.11 `G2-C11` 前后端联动改造

触发：同时修改前端和后端，或前端依赖新增或变更的接口、枚举、错误码、状态或权限。

- [ ] 前后端责任、接口版本和数据权威边界明确。
- [ ] 字段、枚举、空值、错误码、分页和文案映射一致。
- [ ] 新旧前端与新旧后端混用行为、发布顺序和灰度为可执行方案。
- [ ] 联调、契约、权限、异常和回归测试有明确入口。

## 7. `SHOULD` 与 `OBSERVE`

### 7.1 `SHOULD`

- [ ] 方案优先复用现有模块、接口、组件和对象，新增实体有充分理由。
- [ ] 复杂链路使用最少但足够的图，主链路、跨系统链路和持续状态图与正文一致。
- [ ] 关键技术取舍记录备选方案、排除原因和影响。
- [ ] 日志、指标和排障字段支持按租户、业务和 traceId 定位。

### 7.2 `OBSERVE`

观察项必须包含当前依据、指标、责任方、时点、阈值和触发动作。观察结果如果会改变接口、数据、核心流程、任务拆分、验收结果或发布方式，必须在 G2 前关闭，不能留作观察项。

## 8. 角色分工

| 角色 | G2 职责 |
|---|---|
| 方案设计者（产品架构师或研发） | 完成需求澄清、代码调查和技术方案编写；对方案可实施性、证据和开发接管负责 |
| 产品经理 | 处理业务语义问题；确认方案没有改变 PRD 事实；需要变更时回填并升版 PRD |
| 产品架构师 | 确认技术边界、关键选型和准出结论；对 G2 最终放行负责 |
| 研发 | 参与技术检查；确认方案可以被开发接管；不替产品选择业务结果 |
| 测试 | 检查关键功能及关键失败场景是否可测试、可观察、可验收 |

架构师或研发负责技术语言转换和边角澄清。能够从现有资料、项目事实或组织规范唯一确定的技术问题直接记录答案和依据，不转给产品经理。任何澄清如果会改变核心业务结果、权限、状态、数据含义、失败行为或验收结果，必须由产品经理确认并回填 PRD；方案不得自行改写业务事实。

## 9. Jira Agent 执行与输出

### 9.1 执行规则

- 触发场景为 Jira 从“开发设计中”流转到“开发中”，以及人工请求重新执行 G2。
- G2 独立执行，只读取 Jira 主单、PRD、技术方案和项目事实，不读取、不引用、不输出 G1 结论或评论。
- Agent 每次执行全部 6 项 `MUST` 和所有命中 `CONDITIONAL`，不抽样、不使用总分或平均分。
- 单项结果只允许“满足 / 不满足 / N/A”，表示是否构成准出阻断，不表示文档完整度评分。
- 技术方案或 PRD 不可定位、技术方案不可读取，或方案与 PRD 在业务事实上冲突时，直接判定“退回补充”。
- 核心契约无法确认、核心内容相互矛盾或存在第 3.1 节明确阻断情形时，按“不满足”处理；非核心证据缺失、章节缺失、表述不够详细或非关键内容无法唯一判断，不作为退回理由。
- G2 通过前不要求 OpenSpec proposal、tasks 或 Jira 执行子任务已经存在；这些产物在 G2 通过后生成。
- 任一 `MUST` 不满足，或命中的 `CONDITIONAL` 存在影响核心实现、数据权限结果、测试验收或发布安全的缺失时，结论只能为“退回补充”，Jira 禁止流转，OpenSpec `propose` 禁止执行。
- 6 项 `MUST` 的核心契约满足且不存在明确阻断项时，结论为“通过”，允许进入 OpenSpec `propose`；产品架构师在 Jira 留下正式确认后，才构成有效 G2。
- 人工评论可以补充证据或记录架构师澄清，但不能直接把 Agent 的“不满足”改成“满足”。方案修改后必须重新执行完整 G2。

### 9.2 Jira 评论

通过时只输出结论、OpenSpec 权限和材料定位：

```markdown
## G2 技术方案准出结论

- 结论：通过
- OpenSpec propose：允许
- 技术方案：{{Jira 关联文件或路径}}
- PRD：{{路径或链接}}
```

退回补充时只列出不通过的检查项，每个失败项单独一行，不合并，不输出通过项、`N/A` 项、机器判定明细、Due Date、复审范围或阻断项数量：

```markdown
## G2 技术方案准出结论

- 结论：退回补充
- OpenSpec propose：禁止
- 技术方案：{{Jira 关联文件或路径}}
- PRD：{{路径或链接}}

- G2-M03 核心接口契约不完整：缺少错误码和空值语义；研发补充。
- G2-C04 异步失败结果不清：缺少重复消费、补偿和恢复结果；研发补充。
```

失败项统一使用以下单行格式：

```text
G2-{检查项} {问题}；{责任角色}{补充动作}。
```

技术方案不可定位时输出：

```text
- G2-M01 技术方案不可定位：Jira 未关联可读取的技术方案文件；研发补充关联。
```

### 9.3 重新判定

收到技术方案变更、PRD 变更、原型确认、项目证据或架构师澄清后，Agent 必须重新执行全部 `MUST` 和命中的 `CONDITIONAL`。不得只复查上次失败项，也不得因评论文字变化直接改变历史结论。

## 10. 复审与指标

- G2 通过后，开发人员以 PRD、原型、Jira 单和本技术方案为输入，执行 OpenSpec `propose`、生成 tasks，再进入编码、联调、自测和问题修复。
- 如果 OpenSpec `propose` 发现新的系统边界、接口、字段、状态、数据模型、一致性方案、失败结果、验收结果或关键技术选择，必须停止任务生成，修订技术方案并重新 G2。
- 仅进行不改变技术事实的任务拆分、排序或 Jira 子任务创建，不触发重新 G2。
- 必须统计 G2 执行率、无记录流转次数和核心阻断关闭率，目标分别为 100%、0、100%。
- 首次准出通过率只作为改进观察项，不设置惩罚性阈值，不用分数覆盖阻断项。

## 11. 判定示例

| 场景 | 结论 | 原因 |
|---|---|---|
| 简单 CRUD 方案已说明改动模块、核心接口、数据状态和验证入口，未写备选方案、监控指标和详细回滚步骤 | 通过 | 核心契约完整，非关键内容缺失不阻断 |
| 技术方案未写背景复述、代码组织说明或完整任务排序 | 通过 | 不影响核心实现路径、契约和验证入口 |
| 前端需求有原型依据、核心组件复用、状态来源、请求失败结果和验证入口 | 通过 | 核心交互和验证路径可实施，非关键细化不阻断 |
| 前端需求只说“按原型开发”，页面状态、请求失败结果和权限结果均无法确定 | 退回补充 | 核心交互和失败结果存在明确阻断 |
| 技术方案未关联或不可读取 | 退回补充 | G2 无法判断方案是否满足需求 |
| G2 前尚未创建 OpenSpec tasks，但任务拆分约束和依赖边界明确 | 通过 | tasks 在 G2 后生成，不是 G2 的前置材料 |
| 方案修改核心接口，但缺少请求、响应、关键错误或资源权限边界 | 退回补充 | 核心接口契约不完整，会产生不同实现和结果 |
| 方案主链路与 PRD 的状态流转明确冲突 | 退回补充 | 技术方案违反上游业务事实 |
| 多租户写入缺少后端资源归属校验 | 退回补充 | 存在明确的越权风险 |
| 核心功能及关键失败场景没有可识别的测试或验收入口 | 退回补充 | 无法验证核心交付结果 |
| 非关键章节缺失，但核心实现路径、接口、数据状态和验证入口完整 | 通过 | 不构成明确阻断，不输出失败项 |
| LLM 失败策略和副作用保护明确，仅模型参数待实验确认 | 通过，参数在实施前闭环 | 关键业务和技术行为已确定，剩余事项不改变方案边界 |
| 方案依赖 PRD 未定义的降级业务结果 | 退回补充 | 方案不能自行补充产品事实，必须先回填 PRD |
