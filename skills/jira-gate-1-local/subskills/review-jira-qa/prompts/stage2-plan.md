# 测试方案 Prompt

本 Prompt 仅在需求评审通过后执行，并必须读取评审后的需求材料和阶段一需求准入门禁清单。冲突裁决：**契约**（交付物字段、命名、目录、阶段门禁）以 `prompts/contract.md` 为准；**方法**（分析规则、设计细则、合并与判断策略）以本文件为准。

## 输入门禁

- 评审通过后的需求材料及其解析出的 scope
- 与需求材料 Jira Key、需求名称和 scope 一致的需求准入门禁清单
- 可选：原型、接口、环境、历史缺陷和同类用例

缺少评审后的需求材料，或需求准入门禁清单的 Jira Key、需求名称、scope 与需求材料不一致时停止，不得在本阶段补做准入分析后继续，也不得跨目录递归选择同名文件。

门禁**结论**另算：门禁结论为「暂不通过」、门禁已过期或找不到门禁结论时，不在这里停止，由 `locate.mjs` / `design-spec.mjs` 判定为 `not-satisfied` 并以 `SKIPPED` + `applicable=false` 结束。

## 目标

输出可直接用于测试评审、测试设计、排期和资源准备的方案，并明确响应需求准入门禁清单中的不通过项、关闭条件和结论。

## 输出要求

1. 需求摘要与评审结论
2. 测试目标
3. 测试范围
4. 非测试范围
5. 回归影响范围
6. 测试策略与测试类型
7. 测试重点及其对应风险
8. 测试资源依赖
9. 测试环境要求
10. 测试数据要求
11. 入口标准
12. 出口标准
13. 风险与应对措施
14. 待测试点评审确认项

## 分析重点

- 主流程、异常流程、关键规则和状态流转是否可验证
- 权限、上下游、数据一致性和回归影响是否进入范围
- 需求准入门禁清单中的不通过项是否已关闭并有对应验证策略
- 环境、数据、账号、依赖和可观测性是否满足测试投入
- 非测试范围是否明确且有合理依据

## 质量要求

- 不重复输出需求准入门禁清单正文，只引用结论和不通过项并落实验证策略。
- 方案内容必须可执行，体现优先级、资源和入口/出口标准。
- 页面路径、规则或依赖信息不足时列为待确认项，禁止猜测。
- 测试点人工复核后，阶段三必须依据最终 XMind 刷新和修正本方案。

## 输出

记录主需求材料路径、解析后的 scope、Jira Key 和需求准入门禁清单路径，并复用阶段一确认的需求交付根目录：

```text
outputs/<scope>/<JiraKey>/test-plans/<JiraKey>-<需求名称>-测试方案-v<版本>.md
```

scope 为空时路径从 `outputs/<JiraKey>/` 开始。完整需求交付目录、scope 推导与安全规则见 `prompts/contract.md`，本 Prompt 不另行定义。

完成方案和测试用例 XMind 后停止，等待人工复核；不得生成正式测试用例。

生成后先保存到上述 `outputs/...` 路径，再按 `prompts/contract.md`「Jira 附件同步」上传测试方案与测试用例 XMind，删除同名旧版本，只保留最新版本；上传不替代本地保存；上传失败停止并报告。
