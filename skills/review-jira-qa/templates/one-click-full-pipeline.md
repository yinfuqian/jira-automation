# QA 完整链路导航器

本模板只用于判断当前阶段并给出下一条标准命令，不在一次调用中跨越人工审核门禁。完整规则以 `prompts/contract.md` 为准。

## 统一交付目录

三个阶段必须复用同一需求交付根目录：

```text
outputs/<scope>/<JiraKey>/
├── risk-analysis/
├── test-plans/
└── test-cases/
```

scope 由主需求材料在 `inputs/<输入类别>/` 下的相对父目录确定；辅助材料不参与推导。Jira Key、需求名称或 scope 冲突时停止。

## 阶段一：需求评审前

```text
/qa-risk-analysis <Jira需求Key或URL>
```

输出需求准入门禁清单；结论为「通过」时默认进入阶段二，否则停止等待需求评审。

## 阶段二：需求评审通过后

```text
/qa-design <Jira需求Key或URL>
```

阶段二自动读取 Jira 最新需求附件与 `outputs/<scope>/<JiraKey>/risk-analysis/` 下最新需求准入门禁清单；不读取 `inputs/` 旧副本。阶段三同样按 Jira Key 定位最新测试方案与 XMind。

输出测试方案和测试用例 XMind 后停止，等待人工复核方案、正式叶子、页面路径、主要类型和优先级。

阶段二核心验收：

- 无字面“测试点”中间节点，正式叶子使用真实业务模块或操作环节作为标题前缀；
- 一叶一用例，notes 完整，notes 不计为业务子 topic；
- 常规用例使用 2～4 个主要步骤，P0/P1 长链路例外有完整说明；
- 页面路径包含实际导航层级，非页面场景使用真实技术入口；
- 所有前置条件、步骤和预期连续编号，步骤与预期逐项对应；
- 待确认叶子保留建议类型、优先级及完整步骤/预期，且不进入正式交付；
- 普通 UI/正向功能不机械附加跨层检查，重要写操作说明目标变化和必要不变量；
- P0 比例仅用于人工复核，不机械调级；不适用类型不在 XMind 中占位。

## 阶段三：人工复核后

```text
/qa-cases <Jira需求Key或URL>
```

先刷新最终测试方案，再一叶一用例生成 Excel、Xray CSV 和自动化建议。阶段三不重新合并、拆分、定级或分类；Excel 输出中文主要类型和类型统计，Xray CSV 不新增类型映射。

## 禁止行为

- 不得在一次命令内自动连续执行三个阶段。
- 口头“继续”不能替代需求评审通过或人工复核后的正式文件。
- 不得跨 scope 或 Jira 需求目录递归选择同名文件。
- 缺少当前阶段必需输入时，只列阻塞项，不生成下一阶段正式交付物。
- 自动化代码必须在最终测试设计完成且环境、鉴权、账号和技术栈信息充分后另行生成。
