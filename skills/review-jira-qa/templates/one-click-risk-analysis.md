# 一键执行口令：阶段一｜需求准入门禁

本模板只提供需求评审前独立需求准入门禁的阶段入口和验收清单。契约（交付物字段、命名、目录、阶段门禁）以 `prompts/contract.md` 为准；方法（分析规则、设计细则、合并与判断策略）以 `prompts/stage1-gate.md` 为准。

## 标准口令

```text
/review-jira-qa <Jira需求Key或URL>
```

## 输入

- 主需求材料：Jira 单当前最新需求附件，执行时自动读取/下载（必需）；单内无附件或主材料无法唯一确定时，记录 `failedStep=materials` 与缺失项，输出 `ok=false` 结果后返回调用方，不阻塞父流程。
- Jira Issue Key 或完整 `/browse/<IssueKey>` URL：必需。
- 接口、原型、流程、字段、环境和依赖说明：可选，仅作为辅助材料。

## scope 与交付目录

1. scope 由主需求材料在 `inputs/<输入类别>/` 下的相对父目录确定，辅助材料不参与推导；Jira 附件形式的主需求材料先下载到该目录后再解析。
2. 多个主需求材料位于同一输入类别时，使用最深共同父目录；跨类别、无有效共同父目录或存在混放风险时，记录 `failedStep=scope` 并返回调用方，要求显式 scope。
3. inputs 体系外的主需求必须显式提供安全相对 scope；拒绝绝对路径、盘符、`..` 和目录逃逸。
4. Jira Key 必须完整、真实且唯一。

标准输出：

```text
outputs/<scope>/<JiraKey>/risk-analysis/<JiraKey>-<需求名称>-需求准入门禁清单-v<版本>.html
```

scope 为空时从 `outputs/<JiraKey>/risk-analysis/` 开始。

## 执行步骤

1. 解析并展示 Jira Key、需求名称、主需求路径、resolved scope 和需求交付根目录。
2. 提炼用于需求准入门禁判定的摘要，不展开测试设计。
3. 记录需求材料中的缺失、歧义、冲突和不可验证点。
4. 按 `prompts/stage1-gate.md` 的 B1–B7 / C1–C6 判据判定完整性、明确性和可验证性。
5. 为每项不通过项写出事实原文、事实认定和关闭条件。
6. 列出不通过项，按材料冲突/材料未明确归类。
7. 从同一份判定结果生成自包含 HTML。
8. 回读校验 HTML 内容完整、编号连续、材料清单只列 Jira 附件、分析时间在最后一行；无论结论如何，阶段一结束即返回调用方，不自动进入阶段二。
9. HTML 先保存到上述 `outputs/...` 路径，再默认上传 Jira 附件，删除同名需求准入门禁清单旧版本，只保留最新版本；上传不替代本地保存；上传失败记录 `failedStep=upload`、跳过评论并用 `--non-blocking` 输出 `ok=false` 结果后返回调用方，不阻断父流程。
10. 上传后按材料版本同步 Jira 评论：标题 `QA-需求准入门禁结果v<交付物版本>`；正文最后一行写 `材料版本：PRD <版本>（Jira 附件 <ID 列表>）`；通过只写结论，不列不通过项总表；暂不通过写结论 + 总表；同一材料版本复跑编辑同一条评论，材料更新后复跑才新发；持续到复跑结论为「通过」。

## 输出结构（需求准入门禁清单）

阶段一完成需求准入门禁判定；需求准入门禁清单按以下顺序生成：

1. 标题与结论行：`结论：暂不通过：N 项未关闭`。
2. 不通过项总表：编号 1..N；列：`编号 | 类型 | 事项 | 当前问题 | 关闭条件 | 产品需要做什么`。
3. A. 材料冲突：每项只写事实原文、事实认定、关闭条件。
4. B. 材料未明确：每项只写原文、当前问题、关闭条件。
5. 非阻断文字事实：不影响放行，不计入 N。
6. 评审说明：定位、边界、方法依据、材料依据、证据规则、口径说明。
7. 读取材料清单：只列 Jira 附件；分析时间置末。

禁止：内部 Q-xx/R-xx/B 编号、具体改法、如何判定、不接受的关闭方式、本地路径/sha256、旧版本说明、模糊读法。

## 团队验收清单

- [ ] Jira Key、需求名称和 scope 是否唯一且安全？
- [ ] 输出是否位于同一 `outputs/<scope>/<JiraKey>/risk-analysis/`？
- [ ] 辅助材料是否未影响 scope 推导？
- [ ] HTML 是否自包含、内容完整？
- [ ] HTML 是否为 UTF-8、自包含、内嵌 CSS 且无外部资源？
- [ ] 判定是否包含明确原因、影响、建议和待评审问题？
- [ ] 结论是否在首行，且只出现一次？
- [ ] 不通过项编号是否 1..N 连续，无 Q-xx/R-xx/B1 等内部编号？
- [ ] 每项是否只有事实原文、事实认定、关闭条件，没有具体改法？
- [ ] 读取材料清单是否只列 Jira 附件，分析时间是否在最后一行？
- [ ] 阶段一结束后是否已返回调用方、未自动进入阶段二，且未重复生成需求准入门禁清单？
- [ ] 本阶段是否未生成测试方案、测试点、XMind、Excel、CSV 或测试代码？

## 强制门禁

- 本阶段本身不生成测试方案、测试点、XMind、Excel、CSV 或测试代码。
- 阶段一结束即返回调用方，不自动执行阶段二；结论为「通过」时只提示人工触发 `/qa-design`，「暂不通过」或仍有未关闭项时提示修订材料后复跑。运营性失败同样返回调用方，不阻塞父流程。
